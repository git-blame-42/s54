P7 passo a passo: "Meus eventos" do Participante

Pedido típico: "uma página com os Eventos em que o Participante logado está inscrito, com link na navbar". Chance: média-alta. Tempo: 20-30 min.

Exemplo pronto: fvp/4.2/exemplos/p7-meus-eventos/ (patch, bundle e árvore projeto/). Este arquivo é o mesmo conteúdo em formato "um arquivo por vez, com o motivo".

Pré-requisitos: P2 (inscrição do Participante), que está sobre O2 (Eventos para o Participante). O P2 já traz User::enrollments() (HasMany), Enrollment::event(), o EnrollmentsController com create e os testes-base; o O2 traz a rota events.show. O solucao.patch tem 3 commits (O2 + P2 + P7); aqui só o último.

Ordem = fluxo da requisição: rota -> controller -> views -> testes. Schema e model não mudam. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

Arquivos, em ordem

1. config/routes.php

No grupo Route::middleware('auth'), depois de events.show e antes do comentário da inscrição (events.enrollments.create):

    Route::get('/events/{id}', [EventsController::class, 'show'])->name('events.show');

    // Inscrições do usuário logado ("Meus eventos").
    Route::get('/enrollments', [EnrollmentsController::class, 'index'])->name('enrollments.index');

Por quê:

  • Grupo auth: middleware manda quem não tem sessão para /login. Admin e Participante entram; o link só aparece para o Participante.
  • /enrollments + index = listagem RESTful do recurso Inscrições do logado, no mesmo controller do create. Nada de /my-events.
  • use do EnrollmentsController já existe (veio do P2).

2. app/Controllers/EnrollmentsController.php

Novo método no topo da classe, antes de create:

class EnrollmentsController extends Controller
{
    /**
     * "Meus eventos": Inscrições do usuário logado, com o Evento de cada uma.
     */
    public function index(): void
    {
        /** @var array<int, Enrollment> $enrollments */
        $enrollments = $this->currentUser()?->enrollments()->get() ?? [];

        $title = 'Meus eventos';
        $this->render('enrollments/index', compact('enrollments', 'title'));
    }

    public function create(Request $request): void

Por quê:

  • Consulta mora no model: User::enrollments() (HasMany por user_id, do P2). Controller só pede; nada de Enrollment::where(...) aqui.
  • HasMany::get() devolve array<Model>. O @var array<int, Enrollment> diz ao phpstan o tipo real; sem ele, ->event() na view vira erro.
  • currentUser() é ?User: ?-> + ?? []. A rota é auth, mas o phpstan não sabe.
  • Não use User::events(): são os Eventos criados pelo admin (events.user_id), não as Inscrições.
  • $title no compact: o layout imprime <h1><?= $title ?></h1>; faltando, página 500.

Por quê:

  • Pasta enrollments/ = nome passado ao render('enrollments/index').
  • $enrollment->event()->get(): BelongsTo do Enrollment (P2) devolve o Evento. Um SELECT por linha (N+1): aceitável aqui; saiba dizer.
  • Sem Inscrições: mensagem + link. Sem o if, a página fica em branco.
  • htmlspecialchars em texto (XSS); date() só formata.
  • Só título, data e local: resumo. Detalhe e vagas ficam no events.show (O2), via botão "Ver".
  • Catálogo cita botão "Cancelar inscrição" (P3): não está neste patch. Com P3 aplicado, ponha na célula de ações o mesmo form do show (events.enrollments.destroy, _method=DELETE).

7. tests/Acceptance/events/ParticipantMyEventsCest.php (novo)

<?php

namespace Tests\Acceptance\events;

use Tests\Support\AcceptanceTester;

class ParticipantMyEventsCest extends BaseParticipantEventsCest
{
    public function listOnlyMyEventsFromNavbar(AcceptanceTester $page): void
    {
        $page->wantTo('"Meus eventos" lista só as Inscrições do Participante logado');
        $page->amOnPage('/dashboard');
        $page->click('Meus eventos', 'nav');

        $page->seeCurrentUrlEquals('/enrollments');
        $page->see('Meus eventos', 'h1');
        $page->see('Evento 01', 'table');
        $page->see('Evento 03', 'table');
        $page->see('Sala 3', $this->rowOf('Evento 03'));
        $page->see(date('d/m/Y', strtotime($this->startsOn(3))), $this->rowOf('Evento 03'));
        $page->dontSee('Evento 02', 'table');
        $page->seeNumberOfElements('table tbody tr', 2);

        $page->click('Ver', $this->rowOf('Evento 03'));
        $page->seeCurrentUrlEquals("/events/{$this->events[3]->id}");
        $page->see('Você está inscrito neste evento.');
    }

    public function newEnrollmentShowsUpInMyEvents(AcceptanceTester $page): void
    {
        $this->loginAsNewParticipant($page, 'novo@example.com');

        $page->wantTo('Inscrição nova aparece em "Meus eventos"');
        $page->amOnPage('/enrollments');
        $page->see('Você não está inscrito em nenhum evento.');

        $page->amOnPage("/events/{$this->events[2]->id}");
        $page->click('Inscrever-se');
        $page->click('Meus eventos', 'nav');

        $page->see('Evento 02', 'table');
        $page->seeNumberOfElements('table tbody tr', 1);
    }
}

Por quê:

  • Herda de BaseParticipantEventsCest (base O2/P2, sobre BaseEventsCest): 16 Eventos, Participante 1 inscrito nos Eventos 01 e 03, sessão dele; helpers rowOf, startsOn, loginAsNewParticipant.
  • Primeiro: navbar -> lista certa -> "Ver" leva ao detalhe.
  • Segundo: lista vazia, inscreve pelo show, aparece na lista.

Armadilhas (resumo)

  • get() devolve array<Model>: declare /** @var array<int, Enrollment> $enrollments */ para o phpstan.
  • currentUser() é ?User: ?-> e ?? [].
  • N+1 (event()->get() por linha): aceitável, saiba dizer. Alternativa: BelongsToMany em User via event_user (MODEL:365), com nome enrolledEvents() (events() já é dos Eventos criados).
  • Não use User::events() aqui: são os Eventos criados pelo admin.
  • Tabela vazia: mensagem "Você não está inscrito em nenhum evento.".
  • $title fora do compact: página 500.
