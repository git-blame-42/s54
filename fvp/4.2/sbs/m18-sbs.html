M18 passo a passo: Janela de datas: antecedência mínima e limite máximo

Pedido típico: "Evento tem que ser cadastrado com pelo menos 3 dias de antecedência e no máximo 365 dias à frente. Hoje aceita 31/12/9999. Mude a validação do framework e escreva os testes." Chance: média-alta. Tempo: 15-25 min.

Exemplo pronto: fvp/4.2/exemplos/m18-janela-de-datas/ (patch, bundle e árvore projeto/). Pré-requisitos: nenhum (base main). Schema não muda.

Forma do exemplo: estende notPastDate com int $minDays = 0, ?int $maxDays = null no fim (em vez de função nova), constantes STARTS_ON_MIN_DAYS = 3 e STARTS_ON_MAX_DAYS = 365 no Event.

Ordem = fluxo da requisição: lib de validação -> model -> view -> testes. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

1. lib/Validations.php

Três pontos em notPastDate (linhas ~109-138).

a) Docblock, depois da primeira linha ("A data não pode ser anterior a hoje..."):

     * Janela opcional: $minDays exige antecedência mínima (a data deve ser >= hoje + $minDays dias) e
     * $maxDays limita o quanto ela pode estar à frente (<= hoje + $maxDays dias). Com os padrões
     * (0 e null) a regra é só "não passada", sem limite máximo.
     *

b) Assinatura: dois parâmetros novos no fim, depois de $now:

    public static function notPastDate(
        $attribute,
        $obj,
        string $format = 'Y-m-d',
        ?\DateTimeImmutable $now = null,
        int $minDays = 0,
        ?int $maxDays = null
    ) {

c) Depois do if ($date < $today) ("não pode estar no passado!"), antes do return true;, e o helper days() logo abaixo do método:

        if ($minDays > 0 && $date < $today->modify("+{$minDays} days")) {
            $obj->addError($attribute, 'deve ter pelo menos ' . self::days($minDays) . ' de antecedência!');
            return false;
        }

        if ($maxDays !== null && $date > $today->modify("+{$maxDays} days")) {
            $obj->addError($attribute, 'não pode passar de ' . self::days($maxDays) . ' a partir de hoje!');
            return false;
        }

        return true;
    }

    /** "1 dia", "3 dias". */
    private static function days(int $days): string
    {
        return $days === 1 ? '1 dia' : "{$days} dias";
    }

Por quê:

  • Regra reutilizável mora no Validations; o número mora no model.
  • Parâmetros no fim com padrão neutro (0, null): toda chamada antiga de notPastDate continua igual (9999-12-31 ainda passa sem janela).
  • Ordem dos checks: inválida -> passado -> antecedência -> limite. Data passada mantém "não pode estar no passado!" (testes da base contam com ela).
  • $today já vem do método (fuso padrão, setTime(0, 0)); modify soma dias de calendário. Limite inclusivo: +3 e +365 valem.
  • $now injetável (já existia) deixa o teste de limite determinístico.
  • days() só faz o singular ("1 dia").

Armadilha: compare com $today->modify("+N days"), não com strtotime

  • 86400 s.
