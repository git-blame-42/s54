P23 passo a passo: código gravado no registro, exigido para remover ou editar

Pedido típico: "ao cadastrar, o backend gera um código de 4 dígitos (1000 a 9999) que fica gravado no Evento; o admin vê o código no detalhe e só remove o Evento se digitar esse código". Chance: alta. Tempo: 30-40 min. Variante (não implementada no exemplo): exigir o código para salvar uma edição.

Exemplo pronto: fvp/4.2/exemplos/p23-codigo-do-registro-para-remover/ (patch, bundle e árvore projeto/). Sem pré-requisito: parte da main.

Ordem = fluxo da requisição: banco -> model -> controller -> views -> testes. Populate não muda (o construtor gera o código). Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

1. database/schema.sql

Em CREATE TABLE events, logo após capacity (linha ~31):

    capacity    INT NOT NULL,
    -- Código de 4 dígitos gerado pelo model ao criar; o admin digita para remover o Evento.
    confirmation_code SMALLINT UNSIGNED NOT NULL,

Por quê:

  • ActiveRecord não cria coluna. save() manda todas as chaves de $columns; coluna ausente -> Unknown column.
  • SMALLINT UNSIGNED cabe 0-65535: sobra para 9999.
  • Sem UNIQUE: o código é conferido junto com o id (difere de P1).
  • NOT NULL sem DEFAULT: quem garante o valor é o model.

Armadilha: banco de dev não se recria sozinho. ./run db:populate.

d) Construtor e confirmsCode, logo após o ]; de $columns e antes de validates():

    /**
     * Sorteia o código de confirmação só se ele estiver vazio. O construtor também roda a cada leitura do
     * banco (findById, where, Paginator); com o "só se vazio", o código lido nunca é trocado.
     *
     * @param array<string, mixed> $params
     */
    public function __construct($params = [])
    {
        parent::__construct($params);

        $code = $this->confirmation_code;
        if ($code === null || $code === '') {
            $this->confirmation_code = random_int(self::CODE_MIN, self::CODE_MAX);
        }
    }

    /**
     * Confere o código digitado sem conversão: só string de dígitos igual ao código ('04321', ' 4321',
     * null e array não valem). hash_equals compara strings, sem as conversões do ==.
     */
    public function confirmsCode(mixed $input): bool
    {
        if (!is_string($input) || !ctype_digit($input)) {
            return false;
        }

        return hash_equals((string) $this->confirmation_code, $input);
    }

Por quê:

  • @property: atributos são dinâmicos (__get/__set); sem ele o phpstan reclama.
  • $columns: lista que monta INSERT/UPDATE. Sem ela o código não vai ao banco e a coluna NOT NULL lança PDOException.
  • Construtor (molde: User, US:28-35): MODEL:32-42 zera as colunas e copia $params; depois disso o código é sorteado. Populate, EventsAccessTest e BaseEventsCest fazem new Event + save() sem passar pelo controller: o construtor cobre todos.
  • "Só se vazio" é obrigatório: o construtor roda também em toda leitura (MODEL:255, :278, :327 e PAG:143 fazem new static($row)). Sortear sempre = código novo a cada carga; show mostra um, destroy confere outro.
  • confirmsCode(mixed): getParam devolve mixed (null, array). Tipo string no parâmetro -> TypeError (500).
  • ctype_digit + hash_equals: sem (int) ((int) '04321' e (int) ' 4321' viram 4321, (int) '12a' vira 12). hash_equals só aceita string: (string) no valor do banco.
  • Regra no model: controller só pergunta "confere?".
