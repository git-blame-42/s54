1. app/Models/Event.php

Depois do método user(): BelongsTo (linhas ~117-120) e antes de enrollmentsCount():

        return $this->belongsTo(User::class, 'user_id');
    }

    /**
     * Nome de quem cadastrou o Evento (relação BelongsTo com users).
     * A FK fk_events_user garante que o usuário existe.
     */
    public function creatorName(): string
    {
        $creator = $this->user()->get();

        return $creator instanceof User ? $creator->name : '';
    }

Por quê:

  • A relação já existe (user() -> BelongsTo). Só usa: sem SQL novo, sem JOIN à mão.
  • BelongsTo::get() devolve Model, não User (core/Database/ActiveRecord/BelongsTo.php:14). Em app/ o phpstan exige instanceof User antes de ->name.
  • Método no model: regra num só lugar; as duas views só chamam creatorName().
  • '' só satisfaz o tipo: user_id NOT NULL + FK (SCH:35-36) garantem o usuário.

Armadilhas (resumo)

  • get() devolve Model, não User: na view tudo bem; em app/ use instanceof User ou creatorName() no model (melhor).
  • __get mágico permite $event->user->name (MODEL:55-68); prefira a forma explícita user()->get().
  • user_id sem usuário é impossível (FK SCH:35-36); não precisa tratar.
  • Esquecer htmlspecialchars no nome.
  • <td> fora de ordem em relação ao <th>.
