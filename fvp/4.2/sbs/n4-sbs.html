N4 passo a passo: Mudar per_page ou deixar o usuário escolher

Pedido típico: "mostre 10 Eventos por página; depois, deixe o usuário escolher 5, 10 ou 20, sem perder a escolha ao trocar de página". Chance: média-alta. Tempo: 5-10 min (mais 10 com a escolha pelo usuário).

Exemplo pronto: fvp/4.2/exemplos/n4-per-page/ (patch, bundle e árvore projeto/). O patch faz as duas partes. Pré-requisitos: nenhum (parte de main). Schema não muda.

Ordem = fluxo da requisição: model (Paginator e Model::paginate) -> controller -> views -> testes. Rota não muda. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

Só "10 por página" (sem escolha)? Faça só: passo 3a (PER_PAGE = 10), passo 7a e os Cests (8 a 11). Os demais passos são da variante ?per_page=.

c) Método privado novo, antes de findEvent():

    /**
     * `?per_page=` só vale se estiver na lista fechada; qualquer outro valor (0, texto, array) usa o padrão.
     */
    private function perPage(Request $request): int
    {
        $perPage = $request->getParam('per_page');
        if (!is_scalar($perPage) || !ctype_digit((string) $perPage)) {
            return self::PER_PAGE;
        }

        return in_array((int) $perPage, self::PER_PAGE_OPTIONS, true) ? (int) $perPage : self::PER_PAGE;
    }

Por quê:

  • Lista fechada: 0 dá divisão por zero em Paginator::loadTotals (ceil($total / $this->per_page)); valor enorme devolve a tabela inteira. Nunca o valor cru.
  • is_scalar + ctype_digit antes do cast: ?per_page[]=5 é array e (int) 'abc' daria 0. (Versão curta do catálogo, também segura: (int) getParam('per_page', self::PER_PAGE) + in_array(..., [5, 10, 20], true).)
  • per_page nos links só quando difere do padrão: URLs antigas (/admin/events/page/2) não mudam.
  • $perPageOptions via compact: view não lê constante privada.
