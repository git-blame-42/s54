O5 passo a passo: Admin vê e lista só os próprios Eventos

Pedido típico: "cada Administrador só enxerga e cadastra os Eventos dele; paginação contando só os dele; use a relação events() do usuário logado". Chance: média-alta. Tempo: 15-25 min. Pré-requisito: nenhum (parte de main). O exemplo já inclui a restrição de show/edit/update/destroy (ideia do Q1) e o 2º admin no populate (ideia do T1).

Exemplo pronto: fvp/4.2/exemplos/o5-admin-lista-so-proprios/ (patch, bundle e árvore projeto/). Este arquivo é o mesmo conteúdo em formato "um arquivo por vez, com o motivo".

Ordem = fluxo da requisição: controller -> dados -> testes. Sem schema, sem rota, sem view: a relação User::events() e o HasMany::paginate já existem no core. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

1. app/Controllers/Admin/EventsController.php

Quatro pontos.

a) index (linha ~16): trate o null e troque Event::paginate por $owner->events()->paginate:

    /**
     * Lista só os Eventos do Administrador logado (user_id = id dele), paginados.
     */
    public function index(Request $request): void
    {
        $owner = $this->currentUser();
        if ($owner === null) {
            $this->redirectTo(route('users.login'));
            return;
        }

        $paginator = $owner->events()->paginate(
            page: max(1, (int) $request->getParam('page', 1)),
            per_page: self::PER_PAGE,
            route: 'admin.events.paginate'
        );

Resto do método igual (registers(), $title, render).

Por quê:

  • HasMany::paginate passa conditions ao Paginator: o COUNT e o LIMIT já saem filtrados por user_id. "Mostrando 1 - 5 de N" e as páginas contam só os do logado. Sem SQL novo.
  • Argumento nomeado é per_page (com _); perPage: dá erro.
  • currentUser() é ?User: o phpstan exige tratar null mesmo com o middleware garantindo sessão. return depois do redirectTo: o redirectTo é void (o phpstan não sabe que ele dá exit), e no ControllerTestCase ele só imprime Location: ...; sem o return, o código seguiria e chamaria ->events() em null.

Linha removida:

d) Métodos privados, perto do fim (depois de fill, no lugar do findEvent antigo):

    /**
     * Evento novo já com user_id do Administrador logado (events()->new()).
     */
    private function newEvent(): Event
    {
        $event = $this->currentUser()?->events()->new();

        return $event instanceof Event ? $event : new Event();
    }

    /**
     * Só acha Eventos do Administrador logado: o de outro admin vira null e cai em "Evento não encontrado!"
     * (vale para show, edit, update e destroy, sem revelar que o Evento existe).
     */

    {

        return $event instanceof Event ? $event : null;
    }

Antes era return Event::findById((int) $request->getParam('id'));.

Por quê:

  • events()->new() preenche user_id pela relação; dono nunca vem do form (fora de FIELDS).
  • findEvent é o único ponto usado por show, edit, update e destroy: uma troca fecha os quatro. Evento alheio vira null -> "Evento não encontrado!" -> /admin/events, sem revelar que existe.
  • Só filtrar a listagem não basta: a URL /admin/events/{id} ainda abriria o Evento alheio.
  • instanceof Event: HasMany::new/findById devolvem Model/?Model; o phpstan (nível 6) exige converter para Event.
  • ?->: se currentUser() for null, a expressão vira null e cai no fallback.
  • Para deixar o show aberto a todo admin: troque só no show por Event::findById(...).

Armadilhas (resumo)

  • currentUser() é ?User: trate null (redirect + return) ou use ?->; senão phpstan reclama / 500.
  • per_page com _ no argumento nomeado.
  • Sem instanceof Event, phpstan acusa retorno ?Model.
  • Só filtrar a listagem não basta: findEvent com Event::findById ainda abre o Evento alheio por URL.
  • HasMany::paginate não recebe queryParams/orderBy (N1-N4): se esses cenários existirem, monte o Paginator à mão com conditions: ['user_id' => $owner->id, ...].
  • Painel (N6/N7): "meus" ou "todos"? Decida e nomeie.
  • Cests antigos não pegam a mudança (seed é todo do admin logado).
  • 2º admin sem Eventos: "Nenhum evento cadastrado.". Com T1, um só admin2@example.com.
