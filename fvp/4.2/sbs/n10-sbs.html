N10 passo a passo: Página e id inválidos sem conversão silenciosa

Pedido típico: "/admin/events/page/abc mostra a página 1, /admin/events/page/999 mostra tabela vazia e /admin/events/1abc abre o Evento 1. Trate página e id inválidos sem (int) às cegas". Chance: média-alta. Tempo: 15-25 min.

Exemplo pronto: fvp/4.2/exemplos/n10-pagina-id-invalido/ (patch, bundle e árvore projeto/). Sem pré-requisito: sai de main. Schema não muda.

Ordem = fluxo da requisição: Paginator (quem sabe quantas páginas existem) -> controller -> testes. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

1. lib/Paginator.php

Dois pontos.

a) Fim do construtor (linha ~27), loadRegisters() só no intervalo:

    ) {
        $this->loadTotals();
        if (!$this->isOutOfRange()) {
            $this->loadRegisters();
        }
    }

b) Método novo, depois de isPage() e antes de entriesInfo() (linha ~81):

    /**
     * A página pedida não existe: menor que 1 ou depois da última. Sem registros, só a página 1 é válida
     * (a listagem vazia mostra "Nenhum evento cadastrado.").
     */
    public function isOutOfRange(): bool
    {
        return $this->page < 1 || $this->page > max(1, $this->totalOfPages());
    }

Por quê:

  • Quem sabe o total de páginas é o Paginator (totalOfPages(), calculado em loadTotals()). Controller só pergunta: fica fino.
  • loadTotals() roda antes: o COUNT vem primeiro, então isOutOfRange() já pode ser chamado no construtor.
  • Fora do intervalo não consulta à toa nem calcula OFFSET gigante; registers() devolve [] (valor inicial da propriedade).
  • max(1, ...): tabela vazia tem totalOfPages() 0, e a página 1 tem de continuar válida.

Armadilha: sem o max(1, ...), a página 1 vira "fora do intervalo" com tabela vazia e o redirect entra em laço para /page/0.

2. app/Controllers/Admin/EventsController.php

Três pontos. FlashMessage já está importado no topo.

a) index() (linha ~16), validação antes de Event::paginate e checagem logo depois:

    public function index(Request $request): void
    {
        $page = $request->getParam('page') === null ? 1 : $this->positiveInt($request->getParam('page'));
        if ($page === null) {
            FlashMessage::danger('Página inválida!');
            $this->redirectTo(route('admin.events.index'));
            return;
        }

        $paginator = Event::paginate(
            page: $page,
            per_page: self::PER_PAGE,
            route: 'admin.events.paginate'
        );
        if ($paginator->isOutOfRange()) {
            FlashMessage::danger('Página inexistente! Mostrando a última página.');
            $this->redirectTo(route('admin.events.paginate', ['page' => max(1, $paginator->totalOfPages())]));
            return;
        }
        $events = $paginator->registers();

(sai a linha page: max(1, (int) $request->getParam('page', 1)),)

b) findEvent() (linha ~132), troca o corpo:

    private function findEvent(Request $request): ?Event
    {
        // Sem (int) silencioso: "abc" viraria 0 e "1abc" viraria 1 (outro Evento!).
        $id = $this->positiveInt($request->getParam('id'));

        return $id === null ? null : Event::findById($id);
    }

c) Método privado novo, logo depois de findEvent():

    /**
     * Inteiro >= 1 vindo da URL, ou null. Aceita só dígitos (ctype_digit), sem zero à esquerda e sem
     * estourar PHP_INT_MAX; o int é aceito porque os testes de controller passam `['page' => 2]`.
     */
    private function positiveInt(mixed $value): ?int
    {
        if (is_int($value)) {
            return $value >= 1 ? $value : null;
        }

        if (!is_string($value) || !ctype_digit($value) || $value !== (string) (int) $value) {
            return null;
        }

        return (int) $value >= 1 ? (int) $value : null;
    }

Por quê:

  • (int) 'abc' = 0, (int) '1abc' = 1: o max(1, (int) ...) escondia o erro e findById((int) ...) abria ou removia o Evento errado. ctype_digit recusa tudo que não for só dígitos.
  • Parâmetro de rota chega como string ({page}, {id}); teste de controller passa int. Por isso o is_int separado.
  • $value !== (string) (int) $value: recusa 02 (URL canônica única) e o estouro de PHP_INT_MAX com a mesma regra.
  • Sem page (rota /admin/events): getParam dá null -> página 1, como antes.
  • Redirect + flash, não 404: framework não tem 404 própria pra essa rota, o usuário volta a uma listagem útil, e o teste confere Location (mesmo padrão de "Evento não encontrado!").
  • Depois da última vai pra última (não pra 1): é o que acontece ao remover o único Evento da última página.
  • findEvent serve show, edit, update e destroy: id inválido -> null -> "Evento não encontrado!" de sempre nas quatro.

Armadilhas:

  • is_numeric no lugar de ctype_digit: aceita 1.5, 1e3, -1 e 1.
  • ctype_digit(2) (int) é obsoleto no PHP 8.1+ e trata o número como código ASCII: false. Daí o is_int antes.
  • Esquecer o return depois do redirectTo(): no teste de controller o redirect só imprime Location: e o método segue renderizando.
  • Com N1/N4 aplicados, o redirect pra última página tem de levar kind/per_page (array_merge(['page' => ...], $paginator->queryParams())).

3. tests/Unit/Lib/PaginatorTest.php (novo)

Arquivo inteiro:

<?php

namespace Tests\Unit\Lib;

use App\Models\User;
use Tests\TestCase;

class PaginatorTest extends TestCase
{
    private function createUsers(int $total): void
    {
        for ($i = 1; $i <= $total; $i++) {
            $user = new User([
                'name' => "Usuário {$i}",
                'email' => "usuario{$i}@example.com",
                'password' => '123456',
                'password_confirmation' => '123456',
            ]);
            $user->save();
        }
    }

    public function test_is_out_of_range_should_be_false_for_existing_pages(): void
    {
        $this->createUsers(7);

        $this->assertFalse(User::paginate(1, 5)->isOutOfRange());
        $this->assertFalse(User::paginate(2, 5)->isOutOfRange());
    }

    public function test_is_out_of_range_should_be_true_after_the_last_page(): void
    {
        $this->createUsers(7);

        $paginator = User::paginate(3, 5);

        $this->assertTrue($paginator->isOutOfRange());
        $this->assertEquals(2, $paginator->totalOfPages());
        $this->assertSame([], $paginator->registers());
    }

    public function test_is_out_of_range_should_be_true_below_page_one(): void
    {
        $this->createUsers(2);

        $this->assertTrue(User::paginate(0, 5)->isOutOfRange());
        $this->assertTrue(User::paginate(-1, 5)->isOutOfRange());
    }

    public function test_page_one_of_an_empty_table_should_not_be_out_of_range(): void
    {
        $paginator = User::paginate(1, 5);

        $this->assertEquals(0, $paginator->totalOfPages());
        $this->assertFalse($paginator->isOutOfRange());
        $this->assertTrue(User::paginate(2, 5)->isOutOfRange());
    }
}

Por quê:

  • Paginator é de lib/, genérico: testa com User pra não depender de Eventos. paginate() vem do Model, vale pra qualquer model.
  • Cobre os 4 casos: existente, depois da última (sem registros carregados), abaixo de 1, tabela vazia.

Armadilhas (resumo)

  • Parâmetro de rota chega como string; padrão getParam('page', 1) é int: trate os dois (is_int separado, ausente = página 1).
  • ctype_digit('') é false; ctype_digit('007') é true: pra recusar zero à esquerda, compare (string) (int) $page === $page.
  • totalOfPages é 0 sem Eventos: página 1 continua válida (max(1, ...)), senão laço de redirect.
  • (int) 'abc' vira 0 e cai em "não encontrado" por sorte; (int) '12abc' vira 12 e abre outro Evento: é o que a validação fecha.
  • Sem a correção, página além da última nem chega ao entriesInfo: index.phtml mostra "Nenhum evento cadastrado." (falso) e a navegação fica no else, sem link de volta.
  • is_numeric aceita 1.5, 1e3, -1, 1: use ctype_digit.
  • Sem return depois de redirectTo(): segue renderizando.
  • Catálogo sugere flash + volta à página 1 também pra página além da última; o exemplo redireciona pra última. Escolha um e teste.
