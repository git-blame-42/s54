Q3 passo a passo: Ação só para Participante

Pedido típico: "inscrever-se é coisa de participante. O administrador não pode se inscrever em Evento nenhum: se tentar, volta para a área administrativa com um aviso. E esconda o botão 'Inscrever-se' para ele". Chance: média-baixa. Tempo: 20-30 min.

Exemplo pronto: fvp/4.2/exemplos/q3-acao-so-participante/ (patch, bundle e árvore projeto/). Este arquivo é o mesmo conteúdo em formato "um arquivo por vez, com o motivo".

Pré-requisitos: O2 e P2, empilhados (main -> O2 -> P2 -> Q3).

  • O2 (exemplos/o2-eventos-para-participante, guia sbs/o2-sbs.md): área /events, app/views/events/show.phtml, testes de Participante.
  • P2 (exemplos/p2-inscricao-participante, guia sbs/p2-sbs.md): rota POST /events/{id}/enrollments, EnrollmentsController, Enrollment::validates(), botão "Inscrever-se".

O patch traz os 3 commits (O2 + P2 + Q3); aqui só o do Q3.

Duas camadas: middleware participant na rota (barra na porta, redirect para /admin + flash) e regra no model (Enrollment recusa admin em qualquer caminho). Botão escondido é só conforto.

Ordem = fluxo da requisição: model -> middleware -> alias -> rota -> view -> testes. Schema não muda. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

1. app/Models/Enrollment.php

Três pontos.

a) Docblock da classe, @property de user_id:

 * @property int|string|null $user_id

Por quê: o valor pode vir de formulário (string) ou faltar. phpstan precisa saber disso para aceitar o filter_var abaixo.

b) validates(), entre o if dos notEmpty e o da uniqueness:

        if (!Validations::notEmpty('event_id', $this) || !Validations::notEmpty('user_id', $this)) {
            return;
        }

        if (!$this->validatesParticipant()) {
            return;
        }

        if (!Validations::uniqueness(['event_id', 'user_id'], $this)) {

c) Método privado novo, logo depois de validates() (antes do validatesAvailableSpots()):

    /**
     * Só Participante se inscreve. Segunda camada, além do middleware participant da rota:
     * vale também para populate, console e qualquer outro caminho que crie Inscrição.
     */
    private function validatesParticipant(): bool
    {
        // filter_var e não (int): '1abc' viraria o usuário 1.
        $userId = filter_var($this->user_id, FILTER_VALIDATE_INT);
        $user = $userId === false ? null : User::findById($userId);

        if ($user !== null && $user->isAdmin()) {
            $this->addError('base', 'administradores não podem se inscrever em eventos!');
            return false;
        }

        return true;
    }

Por quê:

  • Regra de negócio mora no model: vale para populate, console, outro controller futuro e teste que chama a ação sem router. Se alguém esquecer o middleware numa rota nova, o model ainda recusa.
  • Depois dos notEmpty (precisa de user_id) e antes da uniqueness/vagas: admin não deve ver "já inscrito" nem "sem vagas".
  • return false + return no validates(): para no primeiro erro, como o resto do método.
  • addError('base', ...): o EnrollmentsController (P2) já põe errors('base') no flash danger. Controller não muda.
  • filter_var(..., FILTER_VALIDATE_INT): '1abc' dá false; (int) daria 1, que pode ser o admin.
  • User está no mesmo namespace (App\Models): sem use novo.

Armadilha: P4/P9 mexem na mesma sequência; mantenha validatesParticipant() logo depois dos notEmpty.

2. app/Middleware/Participant.php (novo)

Cópia de app/Middleware/Admin.php com a condição invertida e outro destino:

<?php

namespace App\Middleware;

use Core\Http\Middleware\Middleware;
use Core\Http\Request;
use Lib\Authentication\Auth;
use Lib\FlashMessage;

/**
 * Ações exclusivas do Participante (ex.: inscrever-se). O Administrador é barrado e vai
 * para a área administrativa. Espelho do middleware Admin.
 */
class Participant implements Middleware
{
    public function handle(Request $request): void
    {
        $user = Auth::user();

        // Sem usuário logado, quem redireciona é o middleware Authenticate.
        if ($user !== null && $user->isAdmin()) {
            FlashMessage::danger('Ação disponível apenas para participantes!');
            $this->redirectTo(route('admin.dashboard.index'));
        }
    }

    /**
     * protected (e não private como no Admin) para o teste unitário trocar o exit por um registro.
     */
    protected function redirectTo(string $location): void
    {
        header('Location: ' . $location);
        exit;
    }
}

Por quê:

  • Middleware barra pela rota, antes do controller. Controller fica sem if de perfil. Mesmo mecanismo do admin.
  • implements Middleware: o router chama handle() de cada middleware da rota antes da ação.
  • $user !== null && ...: sem sessão, deixa passar. O grupo interno roda antes do externo, então Participant roda antes do Authenticate; quem manda para /login é o Authenticate, logo em seguida.
  • Destino admin.dashboard.index (/admin): a "casa" do admin. O Admin faz o simétrico com o Participante.
  • redirectTo protected: o dublê do teste sobrescreve e troca header + exit por um registro.

Armadilhas:

  • Redirecionar sem sessão: visitante iria para /admin, não /login.
  • redirectTo private com exit (cópia literal do Admin): sem teste unitário possível.
  • redirectTo duplicado em Admin e Participant: crítica A1 da 4.1. Se cobrarem, extraia para um BaseMiddleware e faça os dois herdarem.

<?php

namespace Tests\Unit\App\Middleware;

use App\Models\User;
use Core\Constants\Constants;
use Core\Http\Request;
use Core\Router\Router;
use Lib\Authentication\Auth;
use Lib\FlashMessage;
use Tests\TestCase;

class ParticipantTest extends TestCase
{
    public function setUp(): void
    {
        parent::setUp();

        // route() precisa das rotas carregadas.
        Router::reset();
        require Constants::rootPath()->join('config/routes.php');

        $_SERVER['REQUEST_METHOD'] = 'POST';
        $_SERVER['REQUEST_URI'] = '/events/1/enrollments';
        unset($_SESSION['user'], $_SESSION['flash']);
    }

    public function tearDown(): void
    {
        unset($_SERVER['REQUEST_METHOD'], $_SERVER['REQUEST_URI'], $_SESSION['user'], $_SESSION['flash']);
        Router::reset();
        parent::tearDown();
    }

    private function createUser(string $role): User
    {
        $user = new User([
            'name' => 'Usuário',
            'email' => "{$role}@example.com",
            'password' => '123456',
            'password_confirmation' => '123456',
            'role' => $role,
        ]);
        $user->save();

        return $user;
    }

    public function test_handle_with_admin_session_should_redirect_to_admin_with_flash(): void
    {
        Auth::login($this->createUser('admin'));
        $middleware = new ParticipantDouble();

        $middleware->handle(new Request());

        $this->assertSame('/admin', $middleware->location);
        $this->assertSame(['danger' => 'Ação disponível apenas para participantes!'], FlashMessage::get());
    }

    public function test_handle_with_participant_session_should_not_redirect(): void
    {
        Auth::login($this->createUser('participant'));
        $middleware = new ParticipantDouble();

        $middleware->handle(new Request());

        $this->assertNull($middleware->location);
        $this->assertSame([], FlashMessage::get());
