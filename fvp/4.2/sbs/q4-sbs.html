Q4 passo a passo: Perfil Organizador com CRUD só dos próprios Eventos

Pedido típico (como no exemplo): "crie o perfil Organizador. Ele entra numa área própria, /organizer/events, e faz o CRUD só dos Eventos que criou. Não entra na Área Administrativa, e o Administrador não entra na dele. No login, o Organizador vai direto para os Eventos dele" (A7 da 4.1 aplicado ao CRUD; junta Q1/O5 com um papel novo). Chance: média. Tempo: 35-40 min.

Exemplo pronto: fvp/4.2/exemplos/q4-perfil-organizador/ (patch, bundle e árvore projeto/). Sem pré-requisito: um commit só, a partir da main (f31006b). Schema muda (ENUM). Duas classes novas em app/ (dump-autoload).

Variante: o catálogo sugere middleware Staff (admin ou organizer) nas mesmas rotas /admin/events, admin vendo tudo. O exemplo dá ao Organizador área separada, /organizer/events, e o admin segue igual em /admin/events. ENUM, isOrganizer(), middleware com alias, restrição por events(), navbar e populate valem nos dois caminhos. Se o pedido for "mesma tela do admin", siga o catálogo (ver Armadilhas).

Ordem = fluxo da requisição: banco -> model -> middleware -> rotas -> controllers -> views -> dados -> testes. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

3. app/Middleware/Organizer.php (novo)

Cópia de app/Middleware/Admin.php, trocando classe, método e mensagem:

<?php

namespace App\Middleware;

use Core\Http\Middleware\Middleware;
use Core\Http\Request;
use Lib\Authentication\Auth;
use Lib\FlashMessage;

class Organizer implements Middleware
{
    public function handle(Request $request): void
    {
        $user = Auth::user();

        // O grupo de rotas mais interno roda primeiro: sem usuário logado este middleware não faz nada e
        // o Authenticate (grupo 'auth', externo, roda depois) redireciona para /login.
        if ($user !== null && !$user->isOrganizer()) {
            FlashMessage::danger('Acesso restrito a organizadores');
            $this->redirectTo(route('dashboard.index'));
        }
    }

    private function redirectTo(string $location): void
    {
        header('Location: ' . $location);
        exit;
    }
}

Por quê:

  • Middleware = filtro antes da ação. Barra quem está logado e não é Organizador (Participante e Administrador) -> /dashboard.
  • RouteWrapperMiddleware::group roda o callback antes de acrescentar o próprio middleware: o grupo interno roda primeiro. Aqui o Organizer roda antes do Authenticate (A17 da 4.1).
  • Por isso o $user !== null: sem login ele deixa passar e o Authenticate, logo depois, manda para /login.

Armadilha: chamar $user->isOrganizer() sem checar null -> erro 500 para visitante, em vez do redirect para /login.

namespace App\Controllers\Organizer;

use App\Controllers\Admin\EventsController as AdminEventsController;
use App\Models\Event;
use App\Models\User;
use Core\Http\Request;
use LogicException;
use Lib\Paginator;

/**
 * CRUD de Eventos do Organizador: o mesmo do Administrador (ações, views e validações), mas
 * só com os Eventos dele (user_id = id do logado), pela relação User::events().
 */
class EventsController extends AdminEventsController
{
    protected const ROUTE_PREFIX = 'organizer.events';

    protected function paginateEvents(int $page): Paginator
    {
        return $this->owner()->events()->paginate(
            page: $page,
            per_page: static::PER_PAGE,
            route: static::ROUTE_PREFIX . '.paginate'
        );
    }

    protected function newEvent(): Event
    {
        $event = $this->owner()->events()->new();

        return $event instanceof Event ? $event : new Event();
    }

    /**
     * Evento de outro usuário vira null e cai em "Evento não encontrado!" (show, edit, update, destroy).
     */
    protected function findEvent(Request $request): ?Event
    {
        $event = $this->owner()->events()->findById((int) $request->getParam('id'));

        return $event instanceof Event ? $event : null;
    }

    private function owner(): User
    {
        $user = $this->currentUser();
        if ($user === null) {
            // Não acontece: as rotas do Organizador ficam dentro do grupo 'auth'.
            throw new LogicException('Área do Organizador acessada sem usuário logado.');
        }

        return $user;
    }
}
