M4 passo a passo: segunda data (ends_on) não anterior a starts_on

Pedido típico: "o Evento passa a ter data de término (ends_on), obrigatória, que não pode ser antes do início; mostre no form, na listagem e no detalhe". Variante: prazo de inscrição (registration_deadline) até a data do Evento. Chance: média-alta. Tempo: 25-35 min.

Exemplo pronto: fvp/4.2/exemplos/m4-segunda-data-ends-on/ (patch, bundle e árvore projeto/). Sem pré-requisito: parte da main. É o roteiro de M1 (campo novo) + validação entre dois campos.

Ordem = fluxo da requisição: banco -> model -> controller -> views -> dados -> testes. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

e) Métodos privados novos, depois de validatesStartsOnNotPast() (termina em Validations::notPastDate('starts_on', $this);, linha ~98), antes do docblock "P02: na edição, a capacidade...":

    /**
     * A data de término não pode ser anterior à de início (no mesmo dia é permitido).
     * Só compara quando as duas datas são válidas; data inválida já tem o próprio erro.
     */
    private function validatesEndsOnNotBeforeStartsOn(): void
    {
        $start = self::parseDate($this->starts_on);
        $end = self::parseDate($this->ends_on);

        if ($start !== null && $end !== null && $end < $start) {
            $this->addError('ends_on', 'não pode ser anterior à data de início!');
        }
    }

    private static function parseDate(mixed $value): ?DateTimeImmutable
    {
        if (!is_string($value)) {
            return null;
        }

        $date = DateTimeImmutable::createFromFormat('!Y-m-d', $value);

        return $date !== false && $date->format('Y-m-d') === $value ? $date : null;
    }

Por quê:

  • Mesmo molde do validatesStartsOnNotPast(): método privado chamado no fim da cadeia, grava erro com addError.
  • parseDate de lib/Validations.php é privado: não dá pra chamar de fora. Copie o createFromFormat('!Y-m-d', ...).
  • ! zera a hora (compara só o dia). format() === $value rejeita 2030-02-31 (que viraria 03/03).
  • null em qualquer das duas -> não compara. Com starts_on inválida, o usuário vê só o erro de starts_on.
  • $end < $start: mesmo dia é válido.
  • Não copie a regra "não no passado" para ends_on (não foi pedida).
