N16 passo a passo: Busca, filtro e ordenação juntos, mantidos na paginação

Pedido típico: "na listagem, busca pelo título, filtro por tipo e ordenação escolhida (coluna e direção), tudo junto e preservado ao trocar de página". Variante: "a listagem aceita ?q=, ?kind=, ?sort= e ?dir=, e o link da página 2 mantém os quatro". Chance: média-alta. Tempo: 35-45 min.

Exemplo pronto: fvp/4.2/exemplos/n16-busca-filtro-ordenacao/ (patch, bundle e árvore projeto/). Sem pré-requisito: sai de main, autocontido (junta N1 forma 2, N2, N3 e N8; não aplique junto com eles). Schema não muda.

Contexto: o framework não tem LIKE nem ORDER BY; where e Paginator só fazem igualdade unida por AND. Hoje a index ignora tudo que não é page e a lista sai sem ORDER BY.

Ordem = fluxo da requisição: Paginator (executa o SQL) -> model (monta WHERE/ORDER BY, valida) -> controller -> views -> testes. Na prova, prioridade: funcionar no navegador, depois testar, depois phpcs.

d) Quatro métodos novos depois de hasEnrollments():

    /**
     * Lê os parâmetros da listagem (q, kind, sort, dir) como chegaram da requisição.
     *
     * Ausente ou vazio: sem busca, todos os tipos, ordem de cadastro, crescente. Inválido: não some
     * calado; ganha uma mensagem na chave do parâmetro e o valor padrão no lugar.
     *
     * @param array<mixed> $params
     * @return array{0: ListingFilters, 1: array<string, string>}
     */
    public static function listingFilters(array $params): array
    {
        $errors = [];

        $q = $params['q'] ?? null;
        $q = is_string($q) ? trim($q) : $q;
        $qValid = $q === null || (is_string($q) && mb_strlen($q) <= 255);
        if (!$qValid) {
            $errors['q'] = 'Busca inválida (até 255 caracteres).';
        }

        $kind = self::choice($params['kind'] ?? null, self::KINDS);
        $sort = self::choice($params['sort'] ?? null, self::SORTS);
        $dir = self::choice($params['dir'] ?? null, self::DIRS);
        $checks = [
            'kind' => [$kind, 'Tipo inválido.'],
            'sort' => [$sort, 'Ordenação inválida.'],
            'dir' => [$dir, 'Direção inválida.'],
        ];
        foreach ($checks as $param => [$value, $message]) {
            if ($value === false) {
                $errors[$param] = $message;
            }
        }

        $filters = [
            'q' => $qValid && is_string($q) ? $q : '',
            'kind' => is_string($kind) ? $kind : null,
            'sort' => is_string($sort) ? $sort : 'id',
            'dir' => is_string($dir) ? $dir : 'asc',
        ];

        return [$filters, $errors];
    }

    /**
     * Uma página da listagem com busca por título, filtro por tipo e ordenação, tudo junto.
     *
     * O WHERE e o ORDER BY são montados aqui; o Paginator usa o mesmo WHERE (e os mesmos valores)
     * no COUNT e na consulta da página, que recebe o ORDER BY e o LIMIT/OFFSET.
     *
     * @param ListingFilters $filters valores lidos por listingFilters()
     */
    public static function listingPage(array $filters, int $page, int $perPage, string $route): Paginator
    {
        $where = '';
        $binds = [];
        if ($filters['q'] !== '') {
            // '!' escapa os curingas do LIKE: "100%" procura o texto "100%", não "100" seguido de qualquer coisa.
            $term = strtr($filters['q'], ['!' => '!!', '%' => '!%', '_' => '!_']);
            $where = "title LIKE :q ESCAPE '!'";
            $binds['q'] = "%{$term}%";
        }

        // Nome de coluna não aceita bind: só entra o que está na lista. O id desempata valores iguais.
        $column = array_key_exists($filters['sort'], self::SORTS) ? $filters['sort'] : 'id';
        $dir = $filters['dir'] === 'desc' ? 'DESC' : 'ASC';
        $order = $column === 'id' ? "id {$dir}" : "{$column} {$dir}, id ASC";
        $kind = $filters['kind'];

        return new Paginator(
            class: static::class,
            page: $page,
            per_page: $perPage,
            table: static::$table,
            attributes: static::$columns,
            conditions: $kind !== null ? ['kind' => $kind] : [],
            route: $route,
            where: $where,
            binds: $binds,
            orderBy: $order,
            queryParams: self::listingQuery($filters),
        );
    }

    /**
     * Query string dos links de página: só o que difere do padrão.
     *
     * @param ListingFilters $filters
     * @return array<string, string>
     */
    public static function listingQuery(array $filters): array
    {
        return array_filter([
            'q' => $filters['q'],
            'kind' => $filters['kind'] ?? '',
            'sort' => $filters['sort'] === 'id' ? '' : $filters['sort'],
            'dir' => $filters['dir'] === 'asc' ? '' : $filters['dir'],
        ], fn(string $value) => $value !== '');
    }

    /**
     * Valor de uma lista fechada: null se ausente ou vazio, false se inválido.
     *
     * @param array<string, string> $allowed
     */
    private static function choice(mixed $value, array $allowed): string|false|null
    {
        if ($value === null || $value === '') {
            return null;
        }

        return is_string($value) && array_key_exists($value, $allowed) ? $value : false;
    }

Por quê:

  • Validação e SQL no model; controller só repassa. SORTS/DIRS servem de allowlist e de rótulo do form (view lê a constante).
  • choice(): três estados. null = ausente/vazio (padrão, sem erro); false = inválido (erro + padrão); string = válido.
  • Inválido não some calado: mensagem na chave do parâmetro, padrão no lugar. Sem 500, sem silêncio.
  • is_string antes de trim/array_key_exists: ?q[]=x chega como array e daria TypeError (500).
  • LIKE com bind (:q): o termo nunca entra no SQL. strtr com array troca !, % e _ numa passada só (o !! gerado não é reescapado): "100%" não acha "100 dias", "a_b" não acha "axb".
  • ESCAPE '!': escape padrão do MySQL é a barra, que também teria de ser escapada; ! explícito vale igual no PostgreSQL.
  • ORDER BY não aceita bind (nome de coluna não é valor): lista fechada. listingPage() é pública e pode ser chamada sem listingFilters(): confere sort de novo e troca dir por ASC/DESC fixos.
  • , id ASC: desempate. Valores iguais saem em qualquer ordem e um Evento poderia aparecer em duas páginas.
  • Padrão id (ordem de cadastro, a da base): testes antigos e CreateSuccessfullyCest seguem verdes.
  • kind vai em conditions (igualdade que o Paginator já sabia fazer).
  • listingQuery() só leva o que difere do padrão: PaginateEventsCest compara URL exata (/admin/events/page/2), e http_build_query mantém '' (?kind=).
  • @phpstan-type ListingFilters: formato do array num lugar só, pro phpstan.

Armadilhas:

  • bindValue(':q', "%{$q}%") sem escapar passa nos testes comuns e falha em "100%" ou "a_b". Escape o ! primeiro.
  • ORDER BY {$request->getParam('sort')}: injeção de SQL.
  • Busca segue a collation (utf8mb4_0900_ai_ci): "oficina" acha "Oficina", "introducao" acha "Introdução".
